# PRD 写作提示

PRD 用来让产品、设计、开发、测试和 Codex 对同一个菜单或模块形成一致理解。产品经理不需要先套固定模板，但要尽量说清楚业务目标、使用角色、页面范围、规则口径和验收标准；Codex 会根据模块类型组织最终结构。

## 先告诉 Codex 这些

| 信息 | 示例 |
| --- | --- |
| 业务目标 | “目前审批分散，主管无法统一查看待处理事项。” |
| 使用角色 | “HRBP、部门主管、员工本人。” |
| 核心任务 | “查看申请、审批、驳回、补充意见、导出记录。” |
| 页面范围 | “列表、详情抽屉、审批弹窗和操作记录。” |
| 关键信息 | “员工、部门、申请时间、当前节点、处理人、状态。” |
| 规则口径 | “驳回必须填写原因，已完成记录不可再次处理。” |
| 待确认项 | “是否支持批量审批需要业务确认。” |

## Codex 会补齐什么

- 页面结构、输入输出、交互逻辑和状态变化。
- 字段、操作、校验、权限、异常和边界场景。
- 面向评审的验收标准和需业务确认事项。
- 与页面、菜单、文档入口对应的实现说明。

## 可以直接这样说

```text
请使用本项目的 prototype-agent skill，为【模块名称】整理 PRD。业务目标是【目标】，使用者是【角色】，他们要完成【任务】，页面需要展示【字段/状态】，可以执行【操作】，业务规则是【规则】。不确定的信息请列为需业务确认事项。
```

# UI 规范摘要

这份文档给产品、设计和评审者快速判断页面方向是否正确。Codex 的完整执行规则位于 `.agents/skills/prototype-agent/references/ui-guidelines.md`，这里不重复展开实现细节。

## 评审时先看这些

| 检查点 | 应该看到 |
| --- | --- |
| 页面目标 | 一个页面只服务一个主要业务任务 |
| 首屏内容 | 直接出现数据、筛选、操作、状态或反馈，而不是大段说明 |
| 组件选择 | 列表用表格，录入用表单，详情用描述与标签页，轻量编辑用抽屉 |
| 操作层级 | 主次按钮清晰，危险操作有确认 |
| 信息密度 | 后台页面应便于扫描、比较和重复操作 |
| 文案范围 | 页面只放业务对象、字段、动作、状态、校验和反馈 |

## 常用页面形态

| 任务 | 页面应该怎么组织 |
| --- | --- |
| 列表管理 | 查询条件、工具栏、表格、分页、行操作 |
| 新建或编辑 | 分组表单、字段校验、保存或提交操作 |
| 审批或流程 | 当前状态、处理动作、流程节点、操作记录 |
| 对象详情 | 关键状态、主操作、基础信息、关联数据、历史记录 |
| 配置维护 | 生效范围、规则输入、校验反馈、发布或回滚动作 |

## 不建议出现

- 为了介绍功能而占据首屏的大段说明。
- 每个列表页都默认加指标卡。
- 用卡片墙展示普通管理数据。
- 多个主按钮并列竞争。
- 删除、停用、驳回等危险动作不做确认。
- 为了视觉丰富添加无业务意义的装饰。

## 需要 Codex 继续处理时

可以直接这样说：

```text
请使用本项目的 prototype-agent skill，检查【页面/模块名称】是否符合 UI 规范摘要和内部执行规则。如发现页面结构、组件选择、操作层级、文案或反馈状态不合适，请直接修复并运行 npm run build。
```

# 产品经理上手指南

这份指南面向需要快速组织后台原型评审的产品经理。你不需要先理解源码文件，也不需要自己判断菜单、路由、文档映射该改哪里；把业务背景、目标用户、页面任务和规则口径说清楚，Codex 会帮你完成 PRD、页面和文档入口的同步调整。

## 你可以让 Codex 接手什么

| 产品工作 | Codex 可以交付什么 |
| --- | --- |
| 明确原型范围 | 修改项目名称、访问页文案、首页说明和评审入口 |
| 新增业务模块 | 先整理 PRD，再实现可评审页面，并同步菜单和文档入口 |
| 细化规则口径 | 把状态流转、字段校验、权限边界和异常场景写进 PRD 与页面 |
| 处理评审反馈 | 把截图、问题点或新要求转成 PRD 与页面修改 |
| 发布前自查 | 检查页面是否可访问、文档是否对应、构建是否通过 |
| 准备预览链接 | 指导 GitHub、Vercel、访问码环境变量和可选自有域名解析配置 |

## 你只需要提供什么

| 信息 | 最简单的表达 |
| --- | --- |
| 业务背景 | “现在【场景/流程】存在【问题】，需要用原型验证【方案】。” |
| 评审对象 | “这次主要给【业务负责人/运营/主管/开发测试】评审。” |
| 页面范围 | “先做【模块名称】，使用者是【角色】，他们要完成【任务】。” |
| 关键信息 | “页面需要看到【字段/列表/状态】，可以执行【操作】。” |
| 规则口径 | “【状态/权限/校验/审批】需要按【规则】处理。” |
| 评审意见 | “这里不符合预期，问题是【问题点】，希望改成【目标效果】。” |
| 发布信息 | “需要发布到【GitHub 仓库/Vercel】，访问码是【规则】，大陆境内访问需要【自有域名/不需要域名】。” |

如果你暂时说不完整，也可以先给一句话。Codex 会先追问最少需要确认的信息，再开始改。

## 推荐启动流程

按下面流程推进。每一步都可以把“可以这样对 Codex 说”里的内容复制给 Codex，让它替你完成。

### 1. 初始化项目

先把模板改成当前项目的名称、评审对象、访问页和首页信息。

可以这样对 Codex 说：

```text
请使用本项目的 prototype-agent skill，把这个模板初始化为【项目名称】原型。这个原型给【用户/评审对象】评审，主要验证【业务目标/流程方案】。如果信息不足，请先问我最少需要确认的问题；确认后请更新项目名称、访问页、首页说明、PRD 和文档入口，最后运行 npm run build。
```

### 2. 新增业务模块

描述模块目标、使用角色、页面任务和规则口径，让 Codex 先写 PRD 再实现页面。

可以这样对 Codex 说：

```text
请使用本项目的 prototype-agent skill，新增【模块名称】业务模块。使用者是【角色】，他们需要完成【任务】，页面需要看到【关键信息】，可以执行【操作】，关键规则是【状态/权限/校验/审批规则】。请先整理 PRD，再做可评审页面，并在完成后运行 npm run build。
```

### 3. 评审后优化

把评审意见交给 Codex，让它同步更新 PRD 和页面实现。

可以这样对 Codex 说：

```text
请使用本项目的 prototype-agent skill，优化【页面/模块名称】。评审反馈是【问题或新要求】，期望效果是【目标效果】。请同步更新 PRD 和页面，确保文档入口仍能打开对应说明，并运行 npm run build。
```

### 4. 发布到 GitHub

确认构建通过后，把项目提交并推送到 GitHub 仓库。这一步很重要，因为 Vercel 推荐连接 GitHub 仓库来自动部署。

可以这样对 Codex 说：

```text
请检查当前原型是否可以发布到 GitHub。请运行 npm run build，确认无误后整理变更摘要，提交代码，并推送到远程 GitHub 仓库。如果缺少远程仓库配置，请告诉我需要提供的仓库地址。
```

### 5. 部署到 Vercel

在 Vercel 连接 GitHub 仓库，选择 Vite 配置，完成部署；访问码在 Vercel 环境变量中配置。

按下面动作推进：

1. 在 Vercel 新建 Project，选择当前 GitHub 仓库。
2. 确认 Framework Preset 为 Vite，Build Command 为 `npm run build`，Output Directory 为 `dist`。
3. 先完成一次部署，确认 Vercel 默认地址可以打开。
4. 进入 Vercel Project 的 Settings -> Environment Variables，添加 `ACCESS_CODES` 和 `ACCESS_SESSION_SECRET`。
5. 重新部署一次，让访问码环境变量生效。
6. 打开 `https://你的域名/access`，确认必须输入访问码后才能进入原型。
7. 如果评审对象在中国大陆境内访问，执行自有域名可选项：购买或申请域名，确定评审子域名，在 Vercel 的 Settings -> Domains 添加域名，复制 Vercel 提示的 DNS 记录，到域名服务商控制台添加解析，等待 Vercel 校验通过，再用自有域名访问 `/access` 验证。

可以这样对 Codex 说：

```text
请根据 docs/vercel-deployment.md 指导我把当前 GitHub 仓库部署到 Vercel。请确认 Framework Preset、Build Command、Output Directory、SPA 路由配置、访问码环境变量；如果大陆境内访问需要自有域名，请把域名购买和 DNS 解析作为可选项列出操作步骤，并给出发布前检查清单。
```

### 6. 发布前检查

发给团队评审前，让 Codex 检查页面、文档入口、PRD、UI 规范和构建状态。

可以这样对 Codex 说：

```text
请使用本项目的 prototype-agent skill，对当前原型做发布前检查。请确认页面是否可访问、顶部文档入口是否正确、PRD 是否同步、UI 规范是否遵守、npm run build 是否通过。如发现问题，请直接修复并说明修改内容。
```

## 需要关注的主要内容

| 内容 | 需要关注什么 | 主要处理方式 |
| --- | --- | --- |
| UI 规范 | 页面是否符合后台产品的信息密度、组件选择和操作层级 | 看 `docs/ui-guidelines.md` 摘要，让 Codex 按内部规则实现 |
| PRD | 每个菜单为什么要做、给谁用、有哪些规则和验收标准 | 让 Codex 先写或同步更新对应 PRD |
| 业务页面 | 评审对象真正看到和操作的原型页面 | 让 Codex 根据 PRD 实现，并同步菜单、路由和文档入口 |
| 发布与访问 | Vercel 部署、访问码环境变量和可选自有域名解析 | 按 `docs/vercel-deployment.md` 做发布前检查 |

## 原型交付前自查

- 页面能正常打开，关键操作能看懂。
- 顶部“文档”能打开当前页面的 PRD、规则说明和相关指南。
- PRD 能让产品、设计、开发、测试和 AI 编码工具准确理解页面范围、业务规则和验收标准。
- 代码已经推送到 GitHub。
- Vercel 已连接 GitHub 仓库并成功部署。
- 如评审对象在中国大陆境内访问，已准备自有域名并完成 Vercel 域名绑定和 DNS 解析。
- `npm run build` 可以通过。
